R1 | correctness | Confidence: medium-high
Where: src/expense.js, splitEvenly (and src/cli.js line 5 and 15, which call it).
Cause -> event -> consequence: each share is rounded independently and no remainder is distributed. Example: splitEvenly(10, 3) gives [3.33, 3.33, 3.33], which sums to 9.99, so one cent is lost. There is also no guard for people = 0, negative, NaN or non-integer. With 0, amount/0 gives Infinity or NaN and the loop produces [] so the CLI prints "Split between 0: " with exit 0. With a non-number argument such as "abc", Number('abc') is NaN, the loop never runs, and the output is an empty split. A negative value likewise gives []. With 2.5 people it produces 3 shares.
Verify: node src/cli.js data/sample.json 3 (sum of shares vs 222.55); node src/cli.js data/sample.json 0; node src/cli.js data/sample.json abc.
Uncertainty: AGENTS.md has no acceptance criterion about the split's sum, so it may be intended prototype behavior.
